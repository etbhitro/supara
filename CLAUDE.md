# Супара: платформа управления центром отдыха

Полное ТЗ (версия 0.3) лежит локально в `docs/TZ.md` и в репозиторий не попадает: репозиторий публичный. Этот файл — краткие правила работы над проектом.

## Что строим

Одна система для трёх направлений Супары (Этно-комплекс, Чункурчак, Талкан): брони, гости, персонал, финансы, склад, AI-агенты и Telegram-боты. Одна БД, разделение по `location_id`.

## Сейчас: МВП без сервера

- `web/` — панель на Next.js (статическая сборка), публикуется на GitHub Pages при каждом push в `main`: https://etbhitro.github.io/supara/
- Один экран (`web/app/page.tsx`): строка запроса и координатор. Ничего не показываем заранее — координатор (`web/lib/coordinator.ts`, по ключевым словам) разворачивает нужную карточку из `web/components/views.tsx`: сводка, шахматка, заявки, задачи, деньги, свободные даты, команда и рабочие места сотрудников. Ссылка `/?q=Сводка` сразу открывает ответ. Без меню, отдельных страниц, пояснений и декора. Заказчик использует Битрикс24: платформа задумана как слой управления поверх него, интеграции в коде пока нет.
- Данных на сервере нет: демо-набор создаётся в браузере и хранится в localStorage (`web/lib/store.tsx`). Гости, количество объектов и цены вымышленные, помечены `[ДОПУЩЕНИЕ]`.
- Агенты в демо работают по правилам, без нейросети (`web/lib/agents.ts`): для Claude API нужен сервер с ключом.
- Интеграции в демо (`web/lib/live.ts`, `web/components/live.tsx`): «Диалоги» (единый inbox WhatsApp/Instagram/Telegram с путём сообщения вебхук → очередь → агент → ответ), «Звонки» (идущий звонок, расшифровка, оценка по чек-листу), «Качество» (рейтинг сотрудников), «Устройства» (камеры, датчики, поток событий, тревога с подтверждением). Это проигрываемые по кругу сценарии с вымышленными людьми, настоящих каналов нет. Настоящая серверная часть — закрытый репозиторий `supara-platform`.
- Три направления: Чункурчак (проживание, `store.tsx` + `agents.ts`), Этно-комплекс (залы-юрты, брони столов и банкеты) и Талкан (заказы конфет) — в `web/lib/locations.ts`. Вместимость залов, брони и заказы условные.
- Оформление: светлая тёплая тема — слоновая кость, эспрессо, бронза (единственный цвет действия); карточки и кнопки из матового стекла; шрифты Golos Text (текст) и Playfair Display (заголовки, крупные цифры, с ровными цифрами); статусы в тёплой земляной гамме, без зелёного и голубого. На фоне еле заметное фото, которое меняется по теме ответа (`sceneOf` в `coordinator.ts`, файлы `web/public/img/`). Тёмную тему, зелёный и яркий декор не возвращать.

## Стек дальше

- Панель: Next.js + TypeScript + Tailwind, адаптив под телефон (основной сценарий). UI-каркас взят из проекта ak-tamga.
- БД и вход: Supabase (Postgres, RLS по ролям и `location_id`, Storage) — подключаем, когда понадобятся реальные данные. Страницы работают только через `useStore()`, его и заменит слой запросов.
- Боты и AI-агенты: сервер + Claude API (с этапа 2 ТЗ)
- Хостинг: DigitalOcean


## Правила

- Работаем по этапам из ТЗ (раздел 10). После каждого этапа: что работает, как проверить, что дальше.
- В публичный репозиторий не попадают: ТЗ, реальные данные гостей, цены закупки, ключи.
- Изоляция (ТЗ 8а): отдельный проект Supabase, отдельный сервер и отдельные ключи. Ничего общего с другими проектами.
- Секреты только в `.env`. Образец: `.env.example`.
- Пересечение броней запрещено на уровне данных (`findConflict` в МВП, exclusion constraint в БД).
- Агенты не подтверждают бронь и не трогают деньги без человека. Все действия агентов пишутся в журнал.
- Допущения помечать `[ДОПУЩЕНИЕ]` и спрашивать до реализации.
